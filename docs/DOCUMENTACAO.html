Sentinel — Monitor de Automações

Centralizador de Heartbeats, Detecção de Ausências (Dead Man's Switch) e Notificações de Erros

1. Visão Geral

O Sentinel é um sistema autônomo e leve, desenvolvido em Python, projetado para monitorar a execução contínua de tarefas agendadas, rotinas batch e robôs de automação corporativos.

"Um script que não roda não consegue enviar uma mensagem avisando que não rodou."

O Sentinel elimina os pontos cegos operacionais atuando em duas frentes complementares:

  • Notificação Ativa de Erros (Push): Intercepta falhas em tempo de execução via decorador, extrai o traceback completo e dispara alertas imediatos com os detalhes do erro.
  • Dead Man's Switch (Monitor de Ausência / Heartbeat): Um vigia contínuo em segundo plano que acompanha os horários previstos de cada rotina. Se um script não enviar o sinal de vida no prazo estipulado, o Sentinel assume a iniciativa e dispara o alerta.

2. O Conceito de Heartbeat e a Falha Silenciosa

Heartbeat (em tradução literal, "batimento cardíaco") é um conceito fundamental na engenharia de software para aferir se um processo está vivo e saudável.

A Analogia Médica do Monitor Cardíaco
Pense no monitor cardíaco de uma UTI hospitalar:
  • Enquanto o paciente está vivo, o aparelho emite batimentos regulares: bip... bip... bip...
  • O médico não precisa perguntar a cada segundo se o paciente está vivo; o batimento contínuo atesta a vida.
  • Se o coração parar de bater (silêncio), o monitor detecta a ausência de sinal e dispara a sirene de emergência: 🚨 PIIIIIIIIII!

Por que arquivos de log tradicionais são cegos para falhas silenciosas?

Sem Heartbeat, você depende de o script executar até o final ou entrar em um bloco try/except para gravar em arquivo de log. Porém, em casos de falhas silenciosas como:

  • Computador desligado acidentalmente ou reiniciado pelo Windows Update;
  • Queda de energia ou perda de conexão de rede local;
  • Agendador de Tarefas do Windows travado ou desabilitado;
  • Falta de memória RAM (OOM) antes mesmo do Python abrir o script.

Nesses casos, o seu script sequer chegou a iniciar. Ele não gerou log, não mandou e-mail e não avisou ninguém.

Com o Heartbeat do Sentinel, a regra se inverte: a ausência de notícia é uma má notícia. Se o script não provar que executou dentro do horário previsto, o Sentinel soa o alarme.

4. Como Funciona a Função Decoradora (@monitor_job)

Um decorador (decorator) funciona como uma "capa protetora" ou um "vigia" colocado em volta de uma função sem alterar uma única linha da regra de negócio que está dentro dela.

As 3 Camadas do Decorador

def monitor_job(job_id: str, name: Optional[str] = None, ...):
    # CAMADA 1: Recebe os parâmetros de configuração (@monitor_job(job_id=...))
    def decorator(func):
        # CAMADA 2: Recebe a função original que foi decorada (ex: def main)
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            # CAMADA 3: O "dublê" que executa no lugar da sua função
            with SentinelMonitor(job_id=job_id, name=name, ...):
                return func(*args, **kwargs)
        return wrapper
    return decorator

O Context Manager SentinelMonitor (Ciclo de Vida)

  1. Antes de Executar (__enter__): Liga o cronômetro (time.time()) e envia um ping HTTP POST para /api/ping/{job_id}/start avisando que o script iniciou. O status no painel muda para ⏳ Executando.
  2. Durante a Execução: A sua automação roda normalmente.
  3. Ao Finalizar com Sucesso: Calcula a duração exata e envia /api/ping/{job_id}/success. O Sentinel atualiza para 🟢 OK e recalcula a próxima data esperada.
  4. Se Ocorrer um Erro: Captura a exceção, extrai o traceback completo, envia para /api/ping/{job_id}/fail (disparando o Telegram) e relança a exceção original para não mascarar o erro no seu script.
Isolamento Operacional
Se o servidor do Sentinel estiver temporariamente desligado ou houver oscilação de rede, o decorador captura a falha de conexão e apenas exibe um aviso suave no console. O script da sua automação nunca é interrompido por falha do monitor.

6. Integração nas Automações

Certifique-se de que o arquivo monitor.py esteja na pasta da automação e adicione o decorador na função principal:

from monitor import monitor_job

@monitor_job(job_id="meu_fechamento_diario", name="Fechamento Diário de Vendas")
def main():
    print("Processando dados...")
    # Se ocorrer qualquer erro, o Sentinel captura e notifica!
    processar_dados()

if __name__ == "__main__":
    main()
Atenção: Regra do try/except
Se a sua automação possui um bloco try/except Exception as e: para gravar arquivos de log próprios, lembre-se de relançar a exceção com raise e ao final do bloco para que o Sentinel receba o alerta.

Integração com PHP

Quando sentinel_monitor.php estiver na mesma pasta da rotina, importe-o e envolva o fluxo principal:

<?php
require_once __DIR__ . '/sentinel_monitor.php';

function executarMonitoramento() {
    // Fluxo principal da automação
}

sentinel_monitor(
    'monitoramento_nf_email',
    'Monitoramento de notas fiscais por e-mail',
    'executarMonitoramento'
);

Substitua die($mensagem) por sentinel_fail($mensagem) para preservar a mensagem e o stack trace no alerta.

Identificação automática da linguagem

O cliente Python envia language: "python" e o cliente PHP envia language: "php" no ping inicial. O dashboard mostra o logotipo do Python ou o elefante do PHP ao lado do nome da rotina. Jobs antigos exibem um ícone neutro até a próxima execução com o cliente atualizado.

Cliente PHP copiado
Se sentinel_monitor.php estiver copiado em outro sistema, substitua a cópia pela versão mais recente para que ela envie o metadado da linguagem.

Scripts PHP com vários ciclos HTTP

Rotinas longas podem continuar o processamento por redirecionamento. Depois de emitir o redirecionamento, use return para finalizar o ciclo monitorado com sucesso. Não use exit, pois o cliente o interpreta como encerramento prematuro.

Exceções capturadas em lotes devem ser relançadas. Fila sem progresso e limite máximo de ciclos devem chamar sentinel_fail(...). Consulte examples/php/analise_nfs_com_sentinel.php.

Retorno bancário Grafeno

O exemplo examples/php/retorno_bancario_grafeno_com_sentinel.php importa o cliente da pasta anterior com require_once __DIR__ . '/../sentinel_monitor.php';. Falhas de API, banco, download, log e cópia são registradas; paginação e troca de empresa terminam o ciclo atual com return.

Proteção de credenciais
Nunca envie ao Sentinel ou ao Telegram o header Authorization nem o token Grafeno. Os alertas devem conter apenas uma descrição resumida da operação que falhou.
